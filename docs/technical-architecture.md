## 二、Dify 配置步骤

### 2.1 前置准备

**需要准备的资源：**
1. Dify 账号（https://dify.ai 或私有化部署）
2. 大模型 API Key（通义千问 / DeepSeek / OpenAI 任选）
3. 本项目的文件（已下载到本地）

**建议使用的模型配置：**
| 用途 | 推荐模型 | 温度 | 最大Token |
|------|----------|------|-----------|
| Agent推理 | 通义千问 Max / GPT-4o | 0.3 | 4096 |
| 知识库检索 | 通义千问 Embedding / text-embedding-3-small | - | - |

---

### 2.2 第一步：创建知识库

**操作步骤：**

1. 登录 Dify 控制台，进入"知识库"页面
2. 点击"创建知识库"，命名为 `瑞幸咖啡菜单知识库`
3. 选择"上传文件"，上传 `agent/knowledge-base/luckin-menu.md`
4. 索引方式选择"高质量"（使用Embedding进行向量索引）
5. 分段设置：
   - 分段标识符：`\n\n`（按空行分段）
   - 最大分段长度：1000 tokens
   - 分段重叠：100 tokens
6. 点击"保存并处理"，等待索引完成

**验证：**
- 索引完成后，在知识库页面点击"测试检索"
- 输入"生椰拿铁多少钱"，应该能检索到生椰拿铁的产品信息
- 输入"黑金会员有什么权益"，应该能检索到会员体系信息

---

### 2.3 第二步：创建 Agent 应用

**操作步骤：**

1. 进入"应用"页面，点击"创建空白应用"
2. 应用类型选择"Agent"
3. 应用名称：`Lucky Growth Agent`
4. 应用描述：`瑞幸用户运营智能体 - 意图驱动的全链路用户增长Agent`
5. 点击"创建"

---

### 2.4 第三步：配置系统提示词

**操作步骤：**

1. 进入应用的"编排"页面
2. 在"系统提示词"区域，粘贴 `agent/system-prompt.md` 的完整内容
3. 提示词开头建议加上以下引导（确保Agent严格遵循格式）：

```
你是 Lucky Growth Agent，瑞幸咖啡的用户运营智能体。
你必须严格按照以下规则工作，不得偏离。

【以下是完整的系统提示词】
```

4. 点击"保存"

**关键提示词要点回顾：**
- 角色定义：瑞幸用户运营专家
- 四层能力：感知→决策→执行→反思
- 六大意图分类体系
- 四阶段生命周期模型
- 置信度三级处理机制
- 结构化输出格式（必须包含意图识别/推荐策略/执行建议/反思记录）
- 2个完整示例对话（高置信度+低置信度）
- 约束与边界（6条禁止项）

---

### 2.5 第四步：配置模型参数

**操作步骤：**

1. 在"编排"页面，找到"模型"设置区域
2. 选择已配置的模型（如通义千问 Max）
3. 参数设置：
   - **温度（Temperature）**：0.3（低温度保证输出稳定，减少幻觉）
   - **最大回复 Token**：4096（确保完整输出结构化结果）
   - **Top P**：0.8
   - **频率惩罚**：0.3
   - **存在惩罚**：0.3
4. 点击"保存"

**为什么温度设为0.3：**
- 用户运营场景需要输出稳定、格式规范
- 低温度减少幻觉和随意发挥
- 创意性主要由提示词中的文案规范和示例引导，而非模型随机性

---

### 2.6 第五步：关联知识库

**操作步骤：**

1. 在"编排"页面，找到"上下文"设置区域
2. 点击"添加知识库"，选择之前创建的 `瑞幸咖啡菜单知识库`
3. 检索设置：
   - 检索模式：混合检索（向量检索 + 全文检索）
   - 召回数量：Top 5
   - 分数阈值：0.5（过滤低相关度结果）
   - 重排序：开启（使用Rerank模型提升检索精度）
4. 点击"保存"

**知识库使用说明：**
- Agent 在推荐产品时，会自动检索知识库获取准确的产品信息（价格、口味、库存等）
- 避免 Agent 编造不存在的产品或错误的价格
- 知识库内容需定期更新（新品上市、价格调整时）

### 2.7 第六步：配置工具（可选但推荐）

Dify Agent 支持自定义工具。以下是建议配置的工具：

#### 工具1：用户画像查询工具
- **功能**：根据用户ID查询用户画像数据（偏好、历史、会员等级等）
- **实现方式**：
  - 方式A：使用 Dify 的"自定义工具"，对接真实用户画像API
  - 方式B（作品集演示用）：使用 Dify 的"代码节点"，返回模拟用户数据
- **输入参数**：user_id（字符串）
- **输出**：用户画像JSON

#### 工具2：菜单检索工具
- **功能**：根据关键词检索菜单产品
- **实现方式**：已通过知识库关联实现，无需额外配置
- 如需更精准的检索，可配置自定义工具对接商品API

#### 工具3：策略匹配工具
- **功能**：根据意图类型和生命周期阶段，查询策略矩阵
- **实现方式**：
  - 方式A：将策略矩阵作为知识库文档上传，通过检索获取
  - 方式B：配置自定义工具，硬编码策略矩阵逻辑
- **输入参数**：intent_type（意图类型）、lifecycle_stage（生命周期阶段）
- **输出**：对应策略配置（产品方向、优惠上限、文案风格）

#### 工具4：优惠计算工具
- **功能**：根据用户阶段和意图，计算合适的优惠力度
- **实现方式**：代码节点，内置优惠力度规则
- **输入参数**：lifecycle_stage、intent_type、user_value
- **输出**：优惠方案（类型、力度、有效期）

**配置工具的操作步骤：**
1. 在"编排"页面，找到"工具"区域
2. 点击"添加工具"，选择工具类型（自定义工具/代码节点/内置工具）
3. 按照工具定义配置参数和逻辑
4. 确保工具描述清晰，让Agent知道何时调用该工具

**注意：** 如果只是做作品集演示，可以不配置工具，直接在用户输入中包含完整的用户画像数据。Agent 会基于输入数据进行推理。

### 2.8 第七步：配置开场白和建议问题

**操作步骤：**

1. 在"编排"页面，找到"开场白"设置

你好，我是 Lucky Growth Agent，瑞幸咖啡的用户运营智能体。

我可以帮你：
1. 分析用户消费意图，生成个性化运营策略

3. 配置建议问题（引导用户测试）：
   - `帮我分析一个周一早8点的黑金会员用户`
   - `一个新注册用户，没有消费数据，怎么运营？`
   - `一个30天没消费的流失用户，怎么召回？`

4. 点击"保存"

**测试步骤：**

1. 在应用页面右侧的"预览"区域，输入测试用例
2. 建议按以下顺序测试：

**测试1：高置信度场景（用例07）**

天气：晴 21°C
位置：公司

预期：意图=习惯复购，置信度≥90%，推荐拿铁大杯，优惠=黑金会员8.5折

**测试2：中置信度场景（用例10）**
```
用户ID：U010

天气：大雨 15°C

```
预期：置信度50-80%，提供两个选项（冰饮vs热饮），建议人工审核

**测试3：低置信度场景（用例19）**
```

位置：未知

```
预期：置信度<50%，不做确定性推荐，输出澄清问题

3. 观察 Agent 的思考过程（ReAct的Thought/Action/Observation）
4. 检查输出是否符合结构化格式要求
5. 记录问题，迭代优化提示词

**常见问题调试：**

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| 输出格式不规范 | 提示词中格式要求不够明确 | 在提示词中增加格式示例，强调必须包含的字段 |
| 意图识别错误 | 分类定义不清晰 | 优化意图分类的定义和判断依据，增加示例 |
| 编造产品信息 | 知识库检索未生效或召回不准 | 检查知识库关联配置，优化检索参数，增加提示词约束 |
| 优惠力度过大 | 策略矩阵约束不够 | 在提示词中明确各阶段优惠上限，增加硬约束 |
| 文案油腻 | 文案规范不够具体 | 增加负面示例（什么是不好的文案），明确禁止用语 |
| 置信度虚高 | 置信度评估标准不明确 | 在提示词中明确置信度计算因素和分级标准 |

## 三、监控看板配置（飞书多维表格）

### 3.1 看板设计

建议创建一个飞书多维表格，用于记录 Agent 的运行日志和效果数据。

**表格结构：**

| 字段名 | 字段类型 | 说明 |
|--------|----------|------|
| 运行ID | 自动编号 | 唯一标识 |
| 运行时间 | 日期时间 | 自动记录 |
| 用户ID | 文本 | 输入的用户ID |
| 场景描述 | 文本 | 简要描述测试场景 |
| 识别意图 | 单选 | 六大意图之一 |
| 置信度 | 数字 | 0-100 |
| 置信度等级 | 公式 | 高/中/低 |
| 生命周期 | 单选 | 新/成长/成熟/流失 |
| 推荐产品 | 文本 | Agent推荐的产品 |
| 优惠方案 | 文本 | Agent推荐的优惠 |
| 文案内容 | 长文本 | Agent生成的文案 |
| 意图识别正确 | 单选 | 是/否（人工标注） |
| 推荐合理 | 单选 | 是/否/部分（人工标注） |
| 文案质量 | 评分 | 1-5分（人工标注） |
| 综合得分 | 公式 | 自动计算 |
| 问题记录 | 长文本 | 记录发现的问题 |
| 迭代版本 | 单选 | V1/V2/V3 |

### 3.2 数据录入方式

- **手动录入**：每次测试后，手动将结果录入表格
- **API自动录入**：通过Dify的Webhook，将运行结果自动推送到飞书多维表格（需要开发）
- **批量导入**：批量测试后，整理成CSV导入

### 3.3 数据看板视图

建议创建以下视图：
1. **全部记录视图**：所有测试记录的列表
2. **按意图分类视图**：按意图类型分组，查看各类的准确率
3. **按迭代版本视图**：按V1/V2/V3分组，对比迭代效果

5. **统计仪表盘**：核心指标的图表展示（准确率趋势、各维度得分等）

## 四、性能优化建议

### 4.1 提示词优化

1. **精简提示词**：在保证效果的前提下，尽量精简提示词长度，降低Token消耗
2. **动态提示词**：使用Dify的变量功能，根据场景动态加载不同的提示词片段
3. **示例精选**：选择最具代表性的2-3个示例，而非堆砌大量示例
4. **分层提示词**：将系统提示词分为"核心规则"（始终加载）和"场景参考"（按需检索）

### 4.2 知识库优化

1. **文档结构优化**：确保知识库文档结构清晰，分段合理
2. **元数据标注**：为每段知识添加元数据（产品分类、价格区间、适用场景等），提升检索精度
3. **检索参数调优**：根据实际效果调整召回数量、分数阈值、重排序开关
4. **定期更新**：新品上市、价格调整时及时更新知识库

### 4.3 模型选择

1. **主力模型**：使用推理能力强的模型（如通义千问 Max、GPT-4o）处理复杂场景
2. **简单场景降级**：对于高置信度的简单场景（如习惯复购），可使用更便宜的模型降低成本
3. **A/B测试**：对比不同模型的效果和成本，选择最优性价比方案

## 五、常见问题 FAQ

### Q1：Dify免费版够用吗？
A：Dify免费版包含200次/天的模型调用，足够用于作品集演示和测试。如果需要更高额度或私有化部署，可考虑付费版或自行部署开源版本。

### Q2：没有API Key怎么办？
A：可以使用Dify内置的免费模型（部分版本提供），或者使用开源模型（如Llama、Qwen）通过Ollama本地部署后接入Dify。

### Q3：Agent输出不稳定怎么办？
A：
1. 降低温度（建议0.2-0.4）
2. 在提示词中增加更明确的格式要求和示例
3. 检查是否有歧义性表述，优化提示词
4. 考虑使用更强的模型

### Q4：知识库检索效果不好怎么办？
A：
1. 检查文档分段是否合理（建议每段300-800 tokens）
2. 开启混合检索和重排序
3. 调整分数阈值（降低可召回更多结果，但可能引入噪音）
4. 优化文档内容，确保信息完整、表述清晰

### Q5：怎么证明这个项目的效果？
A：
1. 使用 `data/test-cases.md` 中的20条测试用例进行标准化测试
2. 记录每条用例的输出，按评估维度打分
3. 整理成评估报告（参考 `evaluation/iteration-comparison.md`）
4. 展示V1→V2→V3的迭代效果提升数据
5. 准备2-3个效果好的演示用例，现场运行展示
