# Lucky Growth Agent 兜底策略设计

> AI PRD 核心模块之一：产品必须给出兜底方案。
> 原则：大模型天然会"长歪"，兜底不是异常处理，是产品设计的一部分。

---

## 一、兜底策略分层框架

```
L1 模型级兜底：单次调用失败（超时/限流/格式错误）
L2 节点级兜底：单个节点输出不可用（提取失败/检索为空/分析异常）
L3 链路级兜底：多节点连续失败或熔断触发
L4 业务级兜底：推荐结果不合理（产品不存在/优惠超限/合规风险）
```

---

## 二、L1 模型级兜底

### 2.1 模型超时

| 节点 | 超时阈值 | 重试策略 | 降级方案 |
|------|----------|----------|----------|
| 参数提取器 | 10s | 重试2次，间隔1s | 三个字段输出空字符串，继续下游 |
| 策略分析 | 15s | 重试1次，间隔2s | 回复生成收到超时标记，输出通用推荐 |
| 回复生成 | 10s | 重试1次，间隔2s | 输出兜底文案（见2.4） |

### 2.2 模型限流（429/rate limit）

- 首次限流：等待 2s 重试
- 二次限流：切换备用模型（deepseek-v4-flash → qwen-turbo）
- 三次限流：降级为规则引擎（不调用模型，基于用户画像+规则模板生成回复）

### 2.3 模型输出格式错误

| 节点 | 错误类型 | 处理方式 |
|------|----------|----------|
| 参数提取器 | 非JSON输出 | 正则提取 `U\d{3}` 作为user_id；其余置空 |
| 策略分析 | 缺少必要段落 | 尝试用关键词匹配提取意图/置信度；失败则标记为"分析异常" |
| 回复生成 | 输出含内部信息 | 关键词检测+重新生成1次；仍不合格则用兜底文案 |

### 2.4 兜底文案库

**通用兜底（全链路异常）：**
> "抱歉，我暂时无法为你推荐。可以告诉我你现在想喝什么口味的吗？比如美式、拿铁还是特调？"

**策略分析超时：**
> "我正在帮你看看适合的咖啡，稍等一下～或者你可以直接告诉我你的口味偏好。"

**知识库为空+无画像：**
> "你好！我是你的咖啡推荐助手。告诉我你平时喜欢喝美式、拿铁还是特调？我来帮你推荐最合适的。"

**新用户无数据：**
> "欢迎来到瑞幸！第一次来试试这几款经典：生椰拿铁（椰香清甜）、经典拿铁（奶咖香浓）、美式（纯粹提神）。今天有新人首杯特惠，想试试哪款？"

## 三、L2 节点级兜底

### 3.1 参数提取器输出异常

| 异常场景 | 检测方式 | 兜底策略 |
|----------|----------|----------|
| user_id 格式非法 | 正则不匹配 `U\d{3}` | user_id 置空，不查询画像 |
| 三个字段全为空 | 输出全为空字符串 | 策略分析按"信息不足"处理，强制低置信度 |
| 提取到不存在的ID | 代码节点返回"未找到" | 策略分析基于场景上下文推荐，不依赖画像 |

### 3.2 用户画像查询失败

| 异常场景 | 兜底策略 |
|----------|----------|
| 代码执行异常 | 返回"画像查询异常"，策略分析基于场景推荐 |
| user_id 为空 | 不查询，策略分析按新用户/未知用户处理 |
| 查询超时（>5s） | 返回"查询超时"，策略分析基于场景推荐 |

**设计原则**：画像查询是增强信息，不是必需依赖。画像不可用时，Agent 仍能基于场景和知识库工作。

### 3.3 知识库检索异常

| 异常场景 | 兜底策略 |
|----------|----------|
| 检索服务超时 | 返回空结果，策略分析基于画像推荐，注明"产品信息以APP为准" |
| 检索结果为空 | 正常流程，策略分析明确说明"知识库暂无相关产品" |
| Embedding服务异常 | 降级为全文检索；仍失败则返回空结果 |
| Rerank服务异常 | 使用向量检索原始Top5，不做重排序 |

**设计原则**：知识库是产品信息来源，不是推荐逻辑的必要条件。知识库不可用时不推荐具体产品，改为询问偏好。

### 3.4 策略分析输出不可用

| 异常场景 | 兜底策略 |
|----------|----------|
| 意图类型不在枚举内 | 默认为"无法确定"，置信度设为30% |
| 置信度缺失或非数值 | 默认为50%（中置信度，需人工审核） |
| 优惠力度超过阶段上限 | 后处理强制截断到上限值 |
| 推荐产品不在知识库中 | 替换为知识库中相似度最高的产品 |

## 四、L3 链路级兜底

### 4.1 熔断机制

**触发条件（满足任一）：**
1. 连续3次全链路执行失败
2. 1小时内用户投诉≥5条
3. 单小时营销成本超预算200%
4. 意图识别准确率实时监测低于60%

**熔断动作：**
1. 立即暂停Agent自主决策
2. 所有策略转人工处理
3. 触发紧急告警（通知运营负责人）
4. 对话场景切换为兜底文案："系统正在升级中，请稍后再试"

**恢复条件：**
1. 人工排查并确认问题修复
2. 小流量灰度测试通过（准确率≥80%）
3. 运营负责人手动确认恢复

### 4.2 降级策略矩阵

| 降级级别 | 触发条件 | 可用能力 | 用户体验 |
|----------|----------|----------|----------|
| L0 正常 | 所有节点正常 | 全链路Agent | 完整个性化推荐 |
| L1 轻度降级 | 知识库不可用 | 画像+场景+策略分析 | 推荐基于画像，产品信息以APP为准 |
| L2 中度降级 | 画像查询不可用 | 场景+知识库+策略分析 | 基于场景推荐，无个性化画像 |
| L3 重度降级 | 策略分析模型不可用 | 规则引擎+模板回复 | 基于规则的通用推荐 |
| L4 熔断 | 连续失败/成本异常 | 兜底文案+人工 | "系统繁忙"提示 |

### 4.3 规则引擎兜底（L3降级）

当模型完全不可用时，基于硬规则生成推荐：

```python
def rule_based_recommend(user_id, scene_context):
    # 1. 有画像 → 基于画像推荐Top1
    if profile and profile['preference']:
        return f"根据你的喜好，推荐{profile['top_product']}"
    # 2. 有时段 → 基于时段推荐
    elif '早晨' in scene_context or '早上' in scene_context:
        return "早晨来杯美式或拿铁，提神醒脑"
    elif '下午' in scene_context:
        return "下午茶时间，生椰拿铁是不错的选择"
    # 3. 什么都没有 → 经典推荐
    else:
        return "推荐试试生椰拿铁或经典美式，今天有优惠活动"
```

## 五、L4 业务级兜底

### 5.1 产品不存在

- 策略分析推荐了知识库中没有的产品
- **兜底**：回复生成前校验产品名是否在知识库中；不在则替换为知识库中最相似的产品

### 5.2 优惠超限

- 策略分析给出的优惠超过用户生命周期阶段上限
- **兜底**：后处理自动截断到上限（如成熟用户最多9折，不能给5折）

### 5.3 合规风险

- 文案包含极限词（"最好喝""第一"）、虚假承诺
- **兜底**：敏感词词库过滤，命中则替换为合规表述；无法替换则重新生成

### 5.4 重复推荐

- 用户最近3天已购买过推荐产品
- **兜底**：策略分析提示"近期已购"，推荐同品类替代产品

## 六、信息补全与多轮追问

### 6.1 何时追问

低置信度（<50%）时，不做确定性推荐，转为追问模式。

### 6.2 追问策略

| 缺失信息 | 追问方式 | 给选项而非开放问题 |
|----------|----------|-------------------|
| 口味偏好 | "你平时喜欢喝什么口味？" | 美式（纯粹提神）/ 拿铁（奶咖香浓）/ 特调（风味丰富） |
| 场景目的 | "现在是什么场合？" | 自己喝提神 / 和朋友分享 / 想试试新品 |
| 价格偏好 | "预算大概多少？" | 10元以内 / 10-20元 / 不限 |
| 温度偏好 | "想喝热的还是冰的？" | 热饮 / 冰饮 / 都可以 |

### 6.3 终止条件

- 最多追问 **2轮**，避免用户疲劳
- 2轮后信息仍不足：基于已有信息给出低置信度推荐，标注"仅供参考"
- 用户明确表示"随便推荐"：直接给出3个经典选项
