## 一、架构总览

### 1.1 设计理念

Lucky Growth Agent 采用"**感知-决策-执行-反思**"四层闭环架构，这是生产级 Agent 的标准架构范式。

设计原则：
1. **意图驱动**：所有决策基于实时意图识别，而非静态用户画像
2. **置信度分级**：高置信度自主执行，中置信度人工审核，低置信度转人工
3. **数据驱动迭代**：每次执行效果都回流，驱动 Prompt 和策略优化
4. **安全可控**：完善的容错兜底和熔断机制，确保生产环境安全

### 1.2 四层架构图

```
┌─────────────────────────────────────────────────────────────┐
│                      反思层 (Reflection)                      │
│  效果评估 │ 失败归因 │ 迭代建议 │ Prompt版本管理 │ 训练样本库  │
└───────────────────────────────┬─────────────────────────────┘
                                │ 优化回流
┌───────────────────────────────▼─────────────────────────────┐
│                      感知层 (Perception)                      │
│  多维度信号采集 │ 实时意图识别 │ 置信度评估 │ 生命周期判断    │
└───────────────────────────────┬─────────────────────────────┘
                                │ 意图+置信度+生命周期
┌───────────────────────────────▼─────────────────────────────┐
│                      决策层 (Decision)                        │
│  策略矩阵匹配 │ 产品推荐 │ 优惠计算 │ 渠道选择 │ 文案生成    │
└───────────────────────────────┬─────────────────────────────┘
                                │ 完整策略
┌───────────────────────────────▼─────────────────────────────┐
│                      执行层 (Execution)                       │
│  多渠道触达 │ 定时/实时执行 │ 状态追踪 │ 效果数据回收        │
└───────────────────────────────┬─────────────────────────────┘
                                │ 效果数据
                                ▼
                         回流至反思层（闭环）
```

## 二、感知层设计

### 2.1 功能定位
感知层是 Agent 的"眼睛和耳朵"，负责采集用户的多维度信号，识别用户当前的消费意图，并评估判断的置信度。

### 2.2 输入信号体系

| 信号维度 | 具体字段 | 数据来源 | 更新频率 | 意图判断权重 |
|----------|----------|----------|----------|--------------|
| **时间维度** | 时段、星期、节假日、发薪日、特殊日期 | 系统时间 | 实时 | 高（30%） |
| **环境维度** | 天气、温度、季节、空气质量 | 第三方API | 实时 | 中（15%） |
| **位置维度** | 公司、家、商场、通勤、门店附近 | GPS/IP定位 | 实时 | 高（25%） |
| **行为维度** | 历史订单、浏览记录、频次趋势、最近消费 | 订单/埋点系统 | 实时 | 高（20%） |
| **社交维度** | 拼单记录、社群活跃度、分享记录 | 社群系统 | 每日 | 低（10%） |

### 2.3 六大意图分类体系

| 意图类型 | 核心特征 | 典型场景 | 偏好产品方向 |
|----------|----------|----------|--------------|
| **提神刚需** | 效率导向、时间敏感、追求浓度 | 工作日早晨、加班、深夜学习 | 美式、浓缩、高咖啡因款 |
| **社交分享** | 场景导向、追求好喝有面子、多人 | 下午茶、聚会、商场购物 | 生椰拿铁、特调、新品、轻食搭配 |
| **放松享受** | 体验导向、愿意尝试、时间充裕 | 周末、假期、休闲时段 | 丝绒拿铁、卡布奇诺、季节限定、精品手冲 |
| **尝鲜探索** | 新奇导向、追求新鲜感、品牌活跃用户 | 新品上市、联名款、限定款发布 | 最新品、限定款、未上市内测 |
| **性价比驱动** | 价格导向、对优惠敏感、囤券偏好 | 促销活动、大促、囤券场景 | 基础款、大额优惠、囤券包 |
| **习惯复购** | 便捷导向、固定偏好、追求效率 | 固定时段、固定产品、高频用户 | 用户历史Top1、"老样子"、一键复购 |

### 2.4 置信度评估机制

置信度计算综合以下因素：
1. **信号完整度**（40%）：关键信号（时间/位置/偏好）是否齐全
2. **判断一致性**（30%）：多维度信号是否指向同一意图
3. **历史匹配度**（20%）：当前场景与用户历史行为的匹配程度
4. **分类清晰度**（10%）：该意图与其他意图的区分度

置信度分级：
- **高置信度（≥80%）**：信号完整、判断一致、历史匹配度高
- **中置信度（50-80%）**：信号部分缺失或存在一定冲突
- **低置信度（<50%）**：关键信息缺失或信号严重冲突

### 2.5 生命周期判断

| 阶段 | 判断标准 | 策略方向 | 优惠上限 |
|------|----------|----------|----------|
| **新用户** | 累计消费1-3杯 | 养成习惯、低门槛体验 | 1.8折首单 |
| **成长用户** | 累计4-10杯，或月消费3-8杯 | 拓展品类、提升频次 | 满减/连续打卡 |
| **成熟用户** | 月消费10杯+，或累计800元+ | 提升客单价、品牌忠诚 | 会员8.5-9折 |
| **预警流失** | 频次下降30%+，或30天+未消费 | 强力召回、分析原因 | 免费一杯/3.8折 |

## 三、决策层设计

### 3.1 功能定位
决策层是 Agent 的"大脑"，基于感知层输出的意图和置信度，通过策略矩阵匹配，自主决策完整的运营策略。

### 3.2 策略矩阵（生命周期 × 意图）

这是 Agent 的核心决策表，共 4×6=24 个交叉单元格，每个单元格对应明确的策略配置。

| 生命周期 \ 意图 | 提神刚需 | 社交分享 | 放松享受 | 尝鲜探索 | 性价比驱动 | 习惯复购 |
|-----------------|----------|----------|----------|----------|------------|----------|
| **新用户** | 首单特惠+经典款 | 拼单优惠+热门款 | 新客尝鲜券+招牌特调 | 新品0元试+联名款 | 1.8折首单+低价基础款 | 首单引导+经典款 |
| **成长用户** | 连续打卡礼+浓度升级 | 第二杯半价+轻食搭配 | 风味探索包+季节限定 | 新品优先尝+口味拓展 | 满减券+高性价比组合 | 频次提升+搭配推荐 |
| **成熟用户** | 会员专属价+一键复购 | 积分翻倍+高端款推荐 | 自由卡特惠+精品手冲 | 内测资格+共创邀请 | 会员日折扣+囤券包 | 老样子+免费升杯 |
| **预警流失** | 回归专属券+老味道唤醒 | 好友邀请礼+社交召回 | 免费一杯+情感化召回 | 新品免费试+新鲜感刺激 | 超大力度券+价格召回 | 老用户专属+回忆杀 |

### 3.3 决策输出字段

每次决策必须输出以下结构化字段：

```json
{
  "recommendation": {
    "product": "产品名称 + 规格",
    "reason": "推荐理由（结合意图和偏好）",
    "alternatives": ["备选产品1", "备选产品2"]
  },
  "promotion": {
    "type": "优惠类型（会员价/满减/折扣券/免费）",
    "value": "具体优惠内容",
    "validity": "有效期"
  },
  "delivery": {
    "channel": "触达渠道（APP/社群/短信/店内）",
    "timing": "执行时机（立即/定时/行为触发）",
    "content": "营销文案"
  },
  "confidence": {
    "level": "高/中/低",
    "score": 0-100,
    "suggestion": "可自主执行/建议人工审核/需澄清信息"
  }
}
```

### 3.4 文案生成规范

**6条硬性规范：**
1. **场景化**：必须贴合用户当前场景，不能千篇一律
2. **有温度**：用朋友式口吻，避免硬广感
3. **行动号召明确**：必须有清晰的下一步行动
4. **长度适配渠道**：APP≤30字，社群≤80字，短信≤50字
5. **禁止油腻称呼**：不用"亲"、"宝宝"、"哦~"等
6. **禁止虚假承诺**：优惠信息必须准确，不夸大

**文案模板库（按意图分类）：**

| 意图 | 文案风格 | 示例 |
|------|----------|------|
| 提神刚需 | 简洁直接、效率感 | "周一早，老样子？大杯美式已备好，一键下单。" |
| 社交分享 | 轻松有趣、社交感 | "下午茶时间到，生椰拿铁第二杯半价，拉上同事一起？" |
| 放松享受 | 温暖治愈、品质感 | "周末了，对自己好一点。丝绒拿铁会员价，慢慢享受。" |
| 尝鲜探索 | 好奇引导、稀缺感 | "新品小黄油拿铁刚上线，会员优先尝鲜，仅限本周。" |
| 性价比驱动 | 直接明了、划算感 | "限时特惠：美式中杯9.9元，囤5杯更划算。" |
| 习惯复购 | 熟悉亲切、便捷感 | "老样子已为你备好，黑金会员8.5折，到店即取。" |

## 四、执行层设计

### 4.1 功能定位
执行层是 Agent 的"手和脚"，负责将决策层生成的策略，通过指定渠道在指定时机执行，并追踪执行状态和效果数据。

### 4.2 多渠道触达矩阵

| 渠道 | 适用场景 | 触达方式 | 文案长度 | 响应速度 | 成本 |
|------|----------|----------|----------|----------|------|
| **APP推送** | 实时推荐、唤醒、复购 | 首页弹窗、消息推送 | ≤30字 | 即时 | 低 |
| **私域社群** | 活动推广、社交分享、新品 | 企业微信群发、一对一 | ≤80字 | 即时 | 低 |
| **短信** | 流失召回、大额优惠 | 短信营销 | ≤50字 | 即时 | 中 |
| **店内推荐** | 到店用户、即时转化 | 门店屏幕、点单屏 | ≤20字 | 即时 | 低 |

### 4.3 执行时机策略

| 时机类型 | 适用场景 | 触发条件 | 示例 |
|----------|----------|----------|------|
| **立即执行** | 高置信度、实时场景 | 用户打开APP、进入门店附近 | 用户打开APP时首页弹窗推荐 |
| **定时执行** | 习惯复购、唤醒 | 用户习惯购买时段前30分钟 | 每周一早8:30推送"老样子"推荐 |
| **行为触发** | 复购、交叉销售 | 用户完成特定行为后 | 用户下单后推荐"搭配轻食立减5元" |

### 4.4 效果数据追踪

每次执行必须追踪以下数据：
- **触达状态**：成功/失败/待发送/已过期
- **用户行为**：点击/忽略/下单/退订/投诉
- **转化数据**：下单金额、下单产品、复购行为
- **成本数据**：渠道成本、优惠成本、总成本

## 五、反思层设计

### 5.1 功能定位
反思层是 Agent 的"学习能力"，负责收集执行效果数据，自动评估策略效果，归因失败案例，生成迭代优化建议，并管理 Prompt 版本。

### 5.2 效果评估指标体系

| 指标层级 | 具体指标 | 计算方式 | 评估频率 |
|----------|----------|----------|----------|
| **Agent能力指标** | 意图识别准确率 | 正确识别数/总测试数 | 每次迭代 |
| | 推荐采纳率 | 采纳推荐数/总推荐数 | 每日 |
| | 文案审核通过率 | 通过数/总生成数 | 每日 |
| | 置信度准确度 | 高置信度中正确的比例 | 每周 |
| **业务效果指标** | 点击率 | 点击数/触达数 | 实时 |
| | 转化率 | 下单数/点击数 | 实时 |
| | 复购率 | 30天内复购用户占比 | 每周 |
| | 客单价 | 总销售额/订单数 | 每周 |
| | 营销ROI | 增量销售额/营销成本 | 每月 |
| **成本效率指标** | 单次触达成本 | 总成本/触达数 | 每周 |
| | 人工审核率 | 需审核数/总案例数 | 每日 |
| | 平均响应时间 | 从触发到输出的时间 | 实时 |

### 5.3 失败案例归因框架

当策略执行效果不佳时，按以下框架归因：

| 失败类型 | 判断标准 | 可能原因 | 优化方向 |
|----------|----------|----------|----------|
| **意图识别错误** | 高置信度但意图判断错误 | 分类标准模糊、信号权重不合理 | 优化意图分类定义、调整信号权重 |
| **推荐不合理** | 意图正确但用户未采纳 | 产品偏好匹配差、推荐理由不充分 | 优化用户画像、改进推荐理由生成 |
| **文案质量差** | 人工审核不通过或用户差评 | 场景化不足、油腻、行动号召不明 | 优化文案规范、增加示例对话 |
| **优惠力度不当** | 转化低或成本超预算 | 力度过大/过小、与用户阶段不匹配 | 调整策略矩阵的优惠上限 |
| **时机/渠道不当** | 触达成功但点击率低 | 时机不对、渠道偏好不匹配 | 优化触达时机算法、渠道选择策略 |
| **工具/系统故障** | 执行失败 | API调用失败、数据异常 | 增加重试机制、降级策略、告警 |

### 5.4 Prompt 版本管理

**版本记录字段：**
- 版本号（V1/V2/V3...）
- 更新日期
- 变更内容（新增/修改/删除了什么）
- 变更原因（基于什么问题或数据）
- 效果对比（迭代前后的核心指标变化）
- 回滚支持（是否支持快速回滚到上一版本）

**迭代验证原则：**
1. 每次迭代后必须运行全部200条测试用例
2. 综合得分提升≥2分才算有效优化
3. 任何维度得分下降超过3分需回滚
4. 所有变更必须记录在案，可追溯、可复现

## 六、人机协同设计

### 6.1 置信度分级处理流程

```
Agent生成策略
      ↓
  置信度评估
   ├─ 高(≥80%) → 自主执行 → 执行后记录供抽检
   ├─ 中(50-80%) → 生成Top3候选 → 推送审核工作台
   │                              ├─ 一键通过 → 执行
   │                              ├─ 修改后通过 → 记录修改 → 执行
   │                              └─ 拒绝 → 记录原因 → 转人工
   └─ 低(<50%) → 不做推荐 → 转人工策略
                      ↓
              人工修改/拒绝记录 → 作为训练样本回流
```

### 6.2 审核工作台设计

**核心功能：**
1. **待审核列表**：按优先级排序（高价值用户优先、即将过期的优先）
2. **候选方案对比**：Top3候选方案并排展示，标注各自的优劣
3. **一键操作**：通过/修改/拒绝，操作不超过2次点击
4. **快速修改**：支持直接编辑产品、优惠、文案字段
5. **审核记录**：所有操作自动记录，包括修改前后对比

**审核效率指标：**
- 平均审核时长：目标≤30秒/条
- 审核通过率：目标≥60%（说明Agent质量高）
- 人工修改率：目标≤30%（说明Agent输出接近可用）

### 6.3 熔断机制

**触发条件（满足任一即触发）：**
1. Agent连续3次执行失败
2. 1小时内用户投诉≥5条
3. 单小时营销成本超出预算200%
4. 意图识别准确率实时监测低于60%

**熔断动作：**
1. 立即暂停Agent自主决策
2. 所有案例转人工处理
3. 触发紧急告警（通知运营负责人）
4. 记录熔断时的系统状态和最近案例

**恢复条件：**
1. 人工排查并确认问题已修复
2. 小流量灰度测试通过（准确率≥80%）
3. 运营负责人手动确认恢复

## 七、技术选型

### 7.1 核心技术栈

| 组件 | 技术选型 | 选型理由 |
|------|----------|----------|
| **Agent平台** | Dify（Agent模式） | 开源、低代码、支持ReAct推理、知识库内置、易于部署 |
| **大模型** | 通义千问 Max / DeepSeek V3 / GPT-4o | 中文理解能力强、推理能力优秀、成本可控 |
| **知识库** | Dify内置向量库 | 与Agent无缝集成、支持混合检索、无需额外运维 |
| **监控看板** | 飞书多维表格 | 低代码、可视化、易于分享、支持自动化 |
| **部署方式** | Dify Cloud / 私有化Docker部署 | 灵活可选，支持SaaS和私有化 |

### 7.2 为什么选择Dify

1. **Agent模式原生支持**：内置ReAct推理循环，支持工具调用和思考过程展示
2. **知识库一体化**：内置向量检索，支持多种文档格式，无需额外搭建
3. **低代码配置**：系统提示词、工具、模型参数都可可视化配置，快速迭代
4. **可观测性**：内置对话日志和调试工具，便于追踪Agent推理过程
5. **开源可扩展**：支持自定义工具、自定义模型、私有化部署
6. **API友好**：提供完整API，便于与业务系统集成

```

上下文数据 ────┤
```

## 九、扩展性设计

### 9.1 横向扩展（新渠道/新场景）
- 新触达渠道：模块化设计，新增渠道只需实现标准接口
- 新业务场景：策略矩阵可扩展，支持新增意图类型和生命周期阶段
- 新品牌/多区域：支持多租户配置，不同品牌可独立配置策略

### 9.2 纵向扩展（能力升级）
- 多轮对话：低置信度场景支持多轮交互澄清意图
- 多模态输入：支持图片（场景照片）、语音输入
- 强化学习：基于用户反馈数据，自动优化推荐策略
- 个性化Prompt：为不同用户群体生成个性化的推荐策略

## 十、安全与合规

### 10.1 数据安全
- 用户数据加密存储和传输
- 最小权限原则，严格控制数据访问权限
- 操作日志完整记录，支持审计追溯
- 符合《个人信息保护法》要求

### 10.2 内容安全
- 营销文案符合广告法，不使用极限词
- 优惠信息准确，不做虚假承诺
- 用户隐私保护，不在输出中暴露敏感个人信息
- 内容审核机制，防止生成违规内容

### 10.3 系统安全
- 熔断机制防止Agent失控
- 优惠力度硬约束防止成本超预算
- 频率限制防止过度营销打扰用户
- 异常检测和告警机制
