# Lucky Growth Agent 演示指南

> 本指南帮助你在面试、比赛、作品集展示中，高效地演示 Lucky Growth Agent 项目。
> 建议演示时长：8-12 分钟（核心演示5分钟 + Q&A 3-7分钟）

---

## 一、演示前准备

### 1.1 环境准备

**必须提前完成：**
- [ ] Dify 账号已注册，Agent 已配置完成并可运行
- [ ] 知识库已上传（`agent/knowledge-base/luckin-menu.md`）
- [ ] 系统提示词已配置（`agent/system-prompt.md`）
- [ ] 模型 API Key 已配置（通义千问/DeepSeek/OpenAI 任选）
- [ ] 至少测试过 5 条用例，确认输出稳定
- [ ] 准备好 2-3 条"效果好"的演示用例（提前跑过，确认输出质量）

**建议准备：**
- [ ] 飞书多维表格看板（Agent 运行日志 + 效果数据）
- [ ] 迭代对比数据截图（V1→V2→V3 效果提升）
- [ ] 项目文档打印版或在线版（PRD、评估报告）

### 1.2 演示用例选择

建议选择以下 3 条用例作为核心演示（覆盖高/中/低三种置信度场景）：

#### 演示用例1：高置信度场景（展示 Agent 自主决策能力）
```
用户ID：U007
时间：周一 9:00
天气：晴 21°C
位置：公司
历史偏好：拿铁大杯（85%）
最近消费：昨天 9:00 拿铁大杯
月消费频次：20杯
会员等级：黑金会员
```
**预期展示点**：
- 意图识别准确（习惯复购，置信度≥90%）
- 推荐"老样子"拿铁大杯
- 优惠策略合理（黑金会员8.5折，不是大额券）
- 文案有温度（"老样子已备好"）
- 输出格式完整规范

#### 演示用例2：中置信度场景（展示人机协同机制）
```
用户ID：U010
时间：周三 14:00
天气：大雨 15°C
位置：公司
历史偏好：冰美式（40%）、冰橙C美式（30%）
最近消费：上周 冰美式
月消费频次：7杯
```
**预期展示点**：
- 意图识别合理（放松/提神，受天气影响）
- 置信度中等（65-80%）
- 提供两个选项（尊重用户冰饮习惯 vs 天气适配推荐热饮）
- 展示"建议人工审核"的处理机制
- 文案有天气共情

#### 演示用例3：低置信度场景（展示 Agent 的自我认知和兜底能力）
```
用户ID：U019
时间：周二 12:00
天气：未知
位置：未知
历史偏好：无（新注册，未消费）
```
**预期展示点**：
- 意图无法确定，置信度<40%
- 不做确定性推荐，而是通过交互获取信息
- 展示"需澄清信息"的处理方式
- 优惠策略合理（首单特惠，低门槛）
- 体现 Agent 不"瞎猜"的专业素养

### 1.3 演示话术准备

提前准备好以下话术：
- 项目介绍（30秒）：一句话讲清楚项目是什么、解决什么问题
- 核心亮点（1分钟）：3个最能体现项目深度的亮点
- 技术方案（1分钟）：Agent架构、核心能力、技术选型
- 迭代过程（1分钟）：V1→V2→V3的优化过程和效果数据
- 项目价值（30秒）：业务价值、个人收获、后续规划

## 二、演示流程（8分钟版）

### 第1分钟：项目介绍（钩子）

**话术模板**：
> "大家好，我今天演示的项目是 Lucky Growth Agent——一个意图驱动的用户运营智能体。
>
> 传统的用户运营是'你买过什么就推什么'的静态个性化，但咖啡消费是高度场景化的——同一个人周一早晨和周五晚上的需求完全不同。
>
> 我的 Agent 能实时感知用户意图、自主决策运营策略、自动执行触达，并基于反馈持续优化。经过三轮迭代，意图识别准确率从68%提升到89%，推荐采纳率从42%提升到71%。"

**展示**：项目封面/架构图（1页PPT或README）

---

### 第2-4分钟：核心功能演示（用例1+用例2）

#### 演示用例1（高置信度，1.5分钟）

**操作**：
1. 在 Dify 运行界面，输入用例1的用户数据
2. 点击运行，展示 Agent 的思考过程和输出
3. 指着输出结果讲解关键点

**讲解要点**：
> "大家看，这是一个黑金会员，每周一早上9点固定买拿铁大杯。
>
> Agent 识别出意图是'习惯复购'，置信度92%——因为时间、位置、历史偏好高度一致。
>
> 推荐的是'老样子'拿铁大杯，优惠是黑金会员8.5折——注意，它没有给3.8折这种大额券，因为成熟用户不需要这么大力度，这就是策略矩阵的约束在起作用。
>
> 文案是'周一早，老样子？大杯拿铁已为你备好，会员价一键下单'——简洁、有温度、行动号召明确。
>
> 最后还有反思记录，Agent 会记录本次决策的关键假设和改进点。"

#### 演示用例2（中置信度，1.5分钟）

**操作**：
1. 输入用例2的用户数据
2. 运行，展示输出

**讲解要点**：
> "这个场景更有意思——用户平时爱喝冰美式，但今天是大雨天，只有15度。
>
> Agent 的意图置信度是72%，属于中置信度。它没有强行推荐，而是给了两个选项：
> - 选项1：老样子冰美式（尊重用户习惯）
> - 选项2：今晚冷，推荐热拿铁（天气适配建议）
>
> 这就是人机协同机制——中置信度场景生成候选方案，建议人工审核，而不是盲目自主决策。
>
> 文案也有天气共情：'雨夜加班辛苦啦。老样子冰美式已备好，或者今晚试试热拿铁暖暖身子？你选。'——不强行改变用户习惯，而是提供选择。"

### 第5分钟：低置信度场景 + 容错机制（用例3）

**操作**：
1. 输入用例3（新用户，信息严重不足）
2. 运行，展示输出

**讲解要点**：
> "这是一个刚注册的新用户，没有任何消费数据，位置天气都未知。
>
> Agent 的置信度只有35%，属于低置信度。它没有瞎猜推荐什么，而是：
> - 明确说明'意图无法确定'
> - 输出需要澄清的问题（'你平时喜欢喝美式、拿铁还是特调？'）
> - 提供低门槛的首单特惠选项
>
> 这体现了 Agent 的自我认知——知道自己什么时候'不知道'，而不是强行给答案。这在生产环境中非常重要，能避免很多糟糕的用户体验。
>
> 另外我们还设计了5大类12个子场景的容错机制，包括产品售罄降级、工具调用失败重试、用户连续不采纳暂停、以及最高优先级的熔断机制——连续3次失败自动暂停自主决策。"

## 三、常见问题与回答准备

### Q1：这个项目和普通的推荐系统有什么区别？

**回答要点**：
- 推荐系统是"基于历史行为的静态匹配"，Agent是"基于实时意图的动态决策"
- 推荐系统只输出"推荐什么"，Agent还要决策"给多大优惠、用什么渠道、写什么文案、什么时机触达"
- 推荐系统是"一次性输出"，Agent有"感知-决策-执行-反思"的完整闭环，能持续自我优化
- 推荐系统没有"置信度"概念，Agent有置信度分级和人机协同机制

### Q2：意图识别的准确率是怎么评估的？

**回答要点**：
- 构建了200条标注测试集（20条核心+180条扩展变体）
- 由本人按统一判定标准独立标注意图类型和生命周期阶段
- 每次Prompt迭代后，运行全部200条用例，统计意图识别准确率
- 采用"严格匹配"标准（意图类型必须完全一致才算正确）
- V1: 68% → V2: 81% → V3: 89%

### Q3：如果Agent推荐错了怎么办？

**回答要点**：
- 多层容错机制：
  1. 置信度分级：低置信度不自主决策，转人工
  2. 中置信度：生成Top3候选，人工审核
  3. 高置信度：自主执行，但有事后抽检
- 5大类12个子场景的具体兜底方案（产品售罄、工具失败、用户不采纳等）
- 熔断机制：连续3次失败自动暂停，转人工
- 反思层：每次失败都记录归因，驱动迭代优化

### Q4：这个项目的技术栈是什么？你写了多少代码？

**回答要点**：
- 核心平台：Dify（Agent模式 + ReAct推理），无需大量编码
- 模型：通义千问 Max（可切换DeepSeek/OpenAI）
- 知识库：Dify内置向量库
- 监控看板：飞书多维表格
- 作为AI产品经理，我的核心工作不是写代码，而是：
  - 设计系统提示词（5000字，三轮迭代）
  - 设计意图分类体系和策略矩阵
  - 构建测试集和评估方法论
  - 设计人机协同和容错机制
  - 撰写PRD和产品文档
- 代码量很少（主要是配置和文档），但产品设计和迭代的深度是核心

### Q5：这个项目能落地吗？和真实生产环境的差距在哪？

**回答要点**：
- 核心能力（意图识别、策略决策、文案生成）已经达到生产级可用标准（准确率89%，文案通过率91%）
- 和真实生产环境的差距主要在：
  1. 数据接入：目前用手动输入模拟，真实环境需要对接CRM/订单/行为数据API
  2. 执行触达：目前只输出策略，真实环境需要对接推送/社群/短信系统
  3. 效果追踪：目前用模拟数据，真实环境需要全链路效果追踪
  4. 规模性能：目前是单实例，真实环境需要支持高并发和多租户
- 但这些都是工程实现问题，产品设计和Agent核心能力已经验证可行

### Q6：为什么选择咖啡/瑞幸这个场景？

**回答要点**：
- 咖啡是高频消费场景，用户运营的价值最明显
- 瑞幸有成熟的私域体系和会员数据，场景真实可信
- 咖啡消费的场景化特征明显（早晨提神、下午社交、周末放松），适合展示"意图驱动"的价值
- 这是2026 AI先锋未来人才大赛的真实命题，有明确的业务背景和评估标准

### Q7：你在这个项目中遇到的最大挑战是什么？怎么解决的？

**回答要点**：
- 最大挑战：V1版本意图识别准确率只有68%，特别是"提神刚需"和"习惯复购"经常混淆（15%的混淆率）
- 解决过程：
  1. 分析混淆案例，发现是因为分类定义不清晰
  2. 重新定义六大意图的判断标准和关键依据
  3. 建立"时间权重+行为一致性+场景匹配度"的判断框架
  4. V2版本混淆率降到7%，准确率提升到81%
- 第二个挑战：文案质量不稳定，经常出现油腻称呼和模板化文案
- 解决：增加6条文案规范+2个完整示例对话（Few-shot），V3文案通过率提升到91%

## 四、演示注意事项

### 4.1 必做
- [ ] 提前测试网络和Dify运行环境
- [ ] 准备好演示用例的输入文本（复制粘贴，不要现场打字）
- [ ] 提前跑一遍演示用例，确认输出稳定
- [ ] 准备好备用截图（万一现场网络不好，用截图演示）
- [ ] 控制时间，核心演示不超过5分钟
- [ ] 讲数据时要自信，因为都是你实际测出来的

### 4.2 禁忌
- ❌ 不要现场调试Prompt或配置
- ❌ 不要念PPT或文档，要讲解
- ❌ 不要说"这个功能还没实现"，要说"这是后续规划"
- ❌ 不要贬低自己的项目，要客观陈述优势和局限
- ❌ 不要超时，留足Q&A时间
- ❌ 不要用太技术的术语，要用产品和业务语言讲解

### 4.3 应急方案

**情况1：Dify现场运行失败/网络不好**
- 应对：直接用提前准备好的输出截图演示，讲解时说"这是我提前运行的结果"

**情况2：Agent输出质量不如预期**
- 应对：坦然说"这个场景确实是边缘案例，也是我们后续优化的方向"，然后展示一个效果好的用例

**情况3：被问到不会的技术问题**
- 应对：诚实说"这个技术细节我没有深入研究，作为产品经理我更关注XX"，然后把话题拉回产品设计和业务价值

**情况4：时间不够**
- 应对：跳过技术架构细节，重点讲核心功能演示和迭代数据，这是最有说服力的部分

## 六、不同场景的演示调整

### 面试场景（10-15分钟）
- 重点：项目深度、个人贡献、AI PM方法论
- 多讲：迭代过程、遇到的挑战、解决思路、个人收获
- 少讲：业务背景介绍（面试官可能更关注你做了什么）
- 必讲：作为AI PM，你和传统PM的区别在哪

### 比赛场景（8-10分钟）
- 重点：业务价值、创新性、落地可行性
- 多讲：解决了什么痛点、效果数据、和现有方案的差异
- 少讲：技术实现细节（评委更关注业务价值）
- 必讲：预期收益和落地路径

### 作品集展示（5-8分钟）
- 重点：完整度、专业度、可运行性
- 多讲：项目结构完整、文档齐全、可实际运行
- 少讲：单个功能的细节
- 必讲：这是一个完整的项目，不是一个方案
