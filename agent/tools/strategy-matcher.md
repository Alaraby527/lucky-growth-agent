# 工具定义：策略匹配（strategy_matcher）

> 工具类型：Dify 自定义工具 / 规则引擎
> 调用方式：Agent 在完成意图识别后调用，获取匹配的运营策略
> 实现方式：方式A - 知识库检索（推荐）；方式B - 代码节点硬编码；方式C - 规则引擎服务

---

## 工具描述

根据意图类型和用户生命周期阶段，从"生命周期 × 意图"策略矩阵中匹配对应的运营策略，包括产品方向、优惠力度上限、文案风格、触达渠道建议。这是 Agent 决策层的核心工具，确保策略选择的一致性和合规性。

**核心作用：防止 Agent 给出超出用户阶段的优惠力度（如给黑金会员发3.8折券），确保营销策略的成本可控。**

---

## 输入参数

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| intent_type | string | 是 | 意图类型（六大类之一） | "提神刚需" |
| lifecycle_stage | string | 是 | 生命周期阶段 | "成熟用户" |
| confidence_level | string | 是 | 置信度等级 | "high"/"medium"/"low" |
| member_level | string | 否 | 会员等级 | "黑金" |
| price_sensitivity | string | 否 | 价格敏感度 | "低" |

## 置信度分级处理规则

| 置信度等级 | 分数范围 | 处理方式 | 输出要求 |
|-----------|----------|----------|----------|
| 高 | ≥80% | 自主执行 | 输出单一最优策略，直接执行 |
| 中 | 50-79% | 人工审核 | 输出Top3候选策略，标注各自优劣，推送审核 |
| 低 | <50% | 转人工/交互澄清 | 不输出确定性策略，输出需澄清的问题列表 |

---

## 优惠力度硬约束

以下约束不可违反，Agent 输出的优惠力度不得超过对应上限：

| 用户阶段 | 最高优惠力度 | 约束原因 |
|----------|-------------|----------|
| 新用户 | 1.8折（首单） | 吸引首单，可接受高成本 |
| 成长用户 | 满减/打卡礼（约5-7折） | 培养习惯，控制成本 |
| 成熟用户 | 会员8.5折 | 已有忠诚度，不需要大额补贴 |
| 流失用户 | 免费一杯/1.8折 | 召回成本可接受，但需控制频次 |

**特殊规则：**
- 单用户单日营销成本不超过15元
- 单用户单月免费饮品不超过2杯
- 成熟用户连续3次自主执行后，第4次需人工抽检
- 任何超过上限的优惠必须人工审批

## 实现方式

### 方式A：知识库检索（推荐）
将策略矩阵文档上传到 Dify 知识库，Agent 在决策时自动检索匹配的策略。

**优点**：零代码、策略更新只需更新文档、可解释性强
**缺点**：依赖检索准确率

### 方式B：代码节点
在 Dify 中使用代码节点，硬编码策略矩阵逻辑：

```python
def main(intent_type: str, lifecycle_stage: str, confidence_level: str) -> dict:
    strategy_matrix = {
        "成熟用户": {
            "提神刚需": {
                "product_direction": "高咖啡因经典款",
                "max_discount": "8.5折",
                "copy_style": "简洁直接",
                "channel": ["APP推送", "一键复购"]
            },
            # ... 更多策略
        }
    }
    
    strategy = strategy_matrix.get(lifecycle_stage, {}).get(intent_type, {})
    
    if confidence_level == "high":
        strategy["action"] = "自主执行"
    elif confidence_level == "medium":
        strategy["action"] = "人工审核"
    else:
        strategy["action"] = "转人工"
    
    return strategy
```

**优点**：速度快、结果100%一致、硬约束可靠
**缺点**：策略更新需要改代码

### 方式C：规则引擎服务
部署独立的规则引擎（如 Drools / 自研），通过 API 提供策略匹配服务。

**优点**：支持复杂规则、可视化配置、A/B测试
**缺点**：开发和运维成本高
