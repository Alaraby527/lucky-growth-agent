# 工具定义：菜单检索（menu_search）

> 工具类型：Dify 知识库检索工具
> 调用方式：Agent 在需要产品信息时自动调用（Dify 内置知识库能力）
> 实现方式：Dify 知识库 + 向量检索（推荐）；或自定义 API 对接商品系统

---

## 工具描述

根据关键词或筛选条件，从瑞幸菜单知识库中检索产品信息，包括产品名称、价格、口味标签、推荐场景、用户画像等。Agent 在推荐产品时调用本工具，确保推荐的产品真实存在、价格准确、信息无误。

**核心作用：防止 Agent 编造不存在的产品或错误的价格信息（幻觉防护）。**

---

## 输入参数

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| query | string | 是 | 检索关键词或自然语言描述 | "提神的咖啡"、"生椰拿铁价格"、"适合下午茶的甜品" |
| category | string | 否 | 产品分类筛选 | "经典咖啡"/"创意特调"/"轻食小食" |
| taste_tags | array | 否 | 口味标签筛选 | ["苦","低卡"] |
| max_price | float | 否 | 最高价格 | 20 |
| limit | integer | 否 | 返回结果数量，默认5 | 3 |

## 检索场景示例

### 场景1：按意图检索产品
**输入：**
```json
{"query": "加班提神 高咖啡因", "limit": 3}
```
**输出：** 美式咖啡、浓缩咖啡、拿铁（按相关度排序）

### 场景2：按口味偏好检索
**输入：**
```json
{"query": "椰香 丝滑 甜", "category": "创意特调", "limit": 3}
```
**输出：** 生椰拿铁、冰吸生椰拿铁

### 场景3：按价格筛选
**输入：**
```json
{"query": "咖啡", "max_price": 15, "limit": 5}
```
**输出：** 美式中杯(13元)、美式大杯(16元-超出)、小鹿茶系列(12-15元)

### 场景4：查询具体产品信息
**输入：**
```json
{"query": "小黄油拿铁 价格 口味"}
```
**输出：** 小黄油拿铁的完整信息（价格21/24元、黄油香、醇厚、复购率高）

### 场景5：搭配推荐
**输入：**
```json
{"query": "下午茶搭配 提拉米苏", "category": "轻食小食"}
```
**输出：** 提拉米苏(15元)、巧克力麦芬(10元)等甜品

## 知识库文档结构

本工具检索的知识库源文件为 `agent/knowledge-base/luckin-menu.md`，包含：

| 知识板块 | 内容 | 检索用途 |
|----------|------|----------|
| 产品分类总览 | 7大分类、价格区间、典型场景 | 按分类浏览 |
| 经典咖啡系列 | 12款产品详细信息 | 产品推荐、价格查询 |
| 创意特调系列 | 5款精选特调 | 新品/特调推荐 |
| 轻食小食系列 | 8款轻食 | 交叉销售、搭配推荐 |
| 会员体系与优惠 | 4级会员、自由卡、7种优惠类型 | 优惠策略计算 |
| 推荐策略矩阵 | 按意图×生命周期的推荐速查表 | 策略匹配参考 |

### 分段策略
- 每个产品作为一个独立分段（chunk）
- 分段长度：300-800 tokens
- 分段重叠：100 tokens
- 元数据标注：产品分类、价格区间、口味标签（用于过滤）

## Dify 知识库配置

### 索引配置
| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 索引模式 | 高质量 | 使用Embedding向量索引 |
| 检索模式 | 混合检索 | 向量检索 + 全文检索 |
| 召回数量 | Top 5 | 召回最相关的5个分段 |
| 分数阈值 | 0.5 | 过滤低相关度结果 |
| 重排序 | 开启 | 使用Rerank提升精度 |

### Embedding 模型
- 推荐：`text-embedding-3-small`（OpenAI）或 `通义千问 Embedding`
- 维度：1536
- 语言：中文优化

## 实现方式

### 方式A：Dify 内置知识库（推荐）
1. 在 Dify 中创建知识库，上传 `luckin-menu.md`
2. 在 Agent 设置中关联知识库
3. Agent 会自动在需要时检索知识库，无需额外开发
4. 系统提示词中增加约束："推荐产品前必须先检索知识库，不得编造产品信息"

### 方式B：自定义 API 工具
对接真实商品管理系统：
- 接口：`GET /api/v1/menu/search?q={query}&category={category}&max_price={max_price}`
- 返回：实时商品数据（含库存状态）
- 优势：数据实时、支持库存校验
- 劣势：需要开发

### 方式C：混合模式
- 产品基础信息走知识库（更新频率低）
- 库存和价格走 API（实时性要求高）
- Agent 先检索知识库获取推荐方向，再调用 API 校验库存和价格

---

## 幻觉防护规则

在系统提示词中明确以下约束：

1. **产品必须来自知识库**：不得推荐知识库中不存在的产品
2. **价格必须准确**：推荐时必须引用知识库中的价格，不得估算
3. **库存校验**：如果工具返回"售罄"，必须推荐替代产品
4. **不确定时检索**：如果对产品信息不确定，必须先调用本工具检索
5. **禁止编造**：不得编造产品描述、优惠活动、用户评价
